# I/O recovery version 1

The frozen development Fourier wide-17 dense trajectory failed at approximately 19.2k updates because Windows denied the atomic replacement of `progress.json.tmp` with `progress.json` in the OneDrive workspace. Its subprocess wall time and partial artifacts remain in the budget ledger. It is not rerun, replaced or counted as a completed scientific comparison.

The original scientific source, architectures, sampling, optimizer, RNG, loss, evaluation and gates are unchanged. Before reserved confirmation, a separately versioned wrapper retries only atomic `os.replace` operations that raise Windows access/share errors 5, 32 or 33. Other errors still propagate. Retry waits are bounded at five seconds, logged in worker stdout, included in external subprocess wall time and subject to the same hard deadline.

The new confirmation manifest includes the wrapper and its test hashes. Every confirmation worker installs the same wrapper, validates the complete source inventory before/after execution, and snapshots the wrapper/tests alongside the unchanged scientific sources. The original development seal is preserved. This is an explicitly recorded infrastructure version; there is no silent reseal of scientific evidence.

Synthetic unreserved tests cover the observed access-lock recovery, exact preserved bytes, non-retryable errors, bounded retry time, explicit wrapper hashing and worker dispatch. No reserved geometry is generated by these tests.
